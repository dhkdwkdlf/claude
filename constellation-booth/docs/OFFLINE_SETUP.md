# 설치·시험 안내 (운영자용)

행사장에서는 Wi-Fi 와 모바일 데이터가 모두 꺼져 있어도 두 앱이 실행·반복되어야 합니다. 설치 방법은 두 가지입니다.

| | **방법 A — 단일 파일 (간단, 권장)** | 방법 B — 홈 화면 앱(PWA) |
|---|---|---|
| 필요한 것 | `별자리운세.html`, `별자리여행.html` 파일 2개 | HTTPS 웹 서버 + 인터넷 되는 곳에서 1회 설치 |
| 설치 | 파일을 태블릿에 복사해서 열기 | 주소 접속 → 홈 화면에 추가 |
| 오프라인 | 파일 자체가 전부라서 항상 동작 | 설치 시 저장된 캐시로 동작(브라우저가 지울 수 있음) |
| 화면 | 첫 터치에 자동 전체화면(주소창 숨김) | 홈 아이콘·전체화면 앱처럼 실행 |
| PC 시험 | **더블클릭** | `npm run preview` 또는 서버 필요 |

처음 시험하실 때와 부스 운영 모두 **방법 A** 를 추천합니다. 홈 화면 아이콘이 꼭 필요할 때만 방법 B 를 쓰세요.

---

## 방법 A — 단일 파일

### PC 에서 바로 시험하기

1. `release/별자리운세.html`, `release/별자리여행.html` 을 PC 에 저장합니다. (`both.zip` 안의 `단일파일/` 폴더에도 있습니다.)
2. 파일을 **더블클릭**하면 Chrome/Edge 에서 바로 열립니다. 인터넷이 없어도 됩니다.
3. 세로 태블릿처럼 보려면 **F12 → 기기 툴바(Ctrl+Shift+M)** 에서 크기를 `600×960` 또는 `800×1280` 으로 맞추고, **터치 시뮬레이션**이 켜진 상태에서 마우스로 끌어 보세요. 그냥 창을 세로로 좁혀도 됩니다.
4. 운영자 화면: 첫 화면의 작은 날짜 글자를 2.5초 안에 5번 클릭하거나 주소 끝에 `#operator` 를 붙입니다. "단일 파일로 실행 중 … 오프라인 준비 완료" 가 보이면 정상입니다.
5. 전체화면으로 보려면 `F11` 또는 운영자 화면의 **전체화면 요청**. (자동 전체화면은 터치에만 반응해서 PC 마우스 클릭으로는 켜지지 않아요. F12 터치 시뮬레이션에서는 켜집니다.)

### 태블릿에 넣기 (Android)

1. 파일 2개를 USB·구글 드라이브·카카오톡 등으로 태블릿에 복사합니다. (다운로드 폴더면 됩니다.)
2. **파일(내 파일) 앱**에서 `별자리운세.html` 을 누르고 **Chrome 으로 열기**를 선택합니다. 한 번 열면 Chrome 주소창 기록에 남으니 다음부터는 Chrome 에서 바로 열 수 있습니다.
3. 화면을 한 번 터치하면 **자동으로 전체화면**이 되어 크롬 주소창과 시스템 바가 사라집니다. 뒤로 가기·앱 전환·새로고침으로 풀려도 다음 터치에 다시 전체화면이 됩니다. (운영자 화면 **자동 전체화면** 체크로 끄고 켤 수 있어요.) 운영자 화면에서 **화면 켜짐 유지**도 눌러 둡니다.
   - 참가자가 앱 밖으로 나가지 못하게 하려면 안드로이드 **앱 고정**을 함께 쓰세요: 설정 → 보안(생체 인식 및 보안) → 기타 보안 설정 → **앱 고정** 켜기 → 최근 앱 화면에서 크롬 아이콘 → **이 앱 고정**. 풀 때는 뒤로 가기+최근 앱 버튼을 함께 길게 누릅니다(기기마다 조금 달라요).
4. 비행기 모드로 바꾼 뒤 Chrome 을 완전히 닫고 다시 열어 동작을 확인합니다.
5. 홈 화면 바로가기가 필요하면 Chrome 메뉴(⋮) → **홈 화면에 추가** 를 눌러 둡니다(바로가기로 열립니다).

### 태블릿에 넣기 (iPad)

- iPad 의 크롬·사파리는 웹페이지 전체화면을 지원하지 않아 자동 전체화면이 동작하지 않습니다. 주소창 없이 쓰려면 방법 B(홈 화면 앱)로 설치하세요.
- iPadOS 의 '파일' 앱에서 HTML 을 열면 미리보기로 열려 일부 기능이 제한될 수 있습니다. **iPad 는 방법 B(홈 화면 앱) 를 권장**합니다. (단일 파일 방식의 iPad 동작은 미검증)

### 알아 둘 것

- 단일 파일 버전은 서비스 워커·설치 과정이 아예 없습니다. 파일이 있으면 동작하고, 지우면 끝입니다.
- 운세 덱 진행·운영자 설정은 브라우저 저장소에 남습니다. 저장이 막힌 환경에서도 메모리로 동작합니다.
- 두 파일은 서로 독립적입니다. 한 파일을 바꿔도 다른 앱에 영향이 없습니다.
- 파일 이름을 바꿔도 됩니다(한글 이름이 불편하면 `fortune.html`, `sky.html` 등).

## 방법 B — 홈 화면 앱(PWA)

인터넷을 끈 채 처음 접속하면 아무것도 내려받을 수 없으므로 **행사 전에 인터넷이 되는 곳에서 한 번 설치**해야 합니다. 파일을 더블클릭해 여는 `file://` 방식으로는 PWA 설치가 되지 않습니다(그 경우는 방법 A 를 쓰세요).

### B-1. 빌드를 서버에 올리기 (개발자·IT 담당)

1. `release/fortune.zip`, `release/sky.zip` 을 받습니다. (또는 `npm run build && npm run package`)
2. 압축을 풀면 `fortune/`, `sky/` 폴더가 나옵니다. 각 폴더를 웹 서버의 **같은 이름의 경로**에 올립니다.
   - `https://서버/fortune/` ← `fortune/` 폴더 내용
   - `https://서버/sky/` ← `sky/` 폴더 내용
   - 경로를 바꾸려면 `apps/*/vite.config.ts` 의 `base` 와 `manifest.webmanifest` 의 `start_url`·`scope`·`id` 를 함께 바꾼 뒤 다시 빌드합니다.
3. 서버 설정 권장값: `index.html`, `sw.js` 는 `Cache-Control: no-cache`; `assets/*` 는 장기 캐시 가능; `*.webmanifest` → `application/manifest+json`, `*.woff2` → `font/woff2`, `*.webp` → `image/webp`.
4. 간단 검수용: 저장소에서 `npm run preview` 를 실행하면 `http://localhost:4173/fortune/`, `/sky/` 로 열 수 있습니다. `localhost` 는 보안 컨텍스트로 취급되어 서비스 워커가 동작합니다. 태블릿에서 PC 로 접속할 때는 HTTPS 가 아니면 설치가 되지 않습니다.

### B-2. 태블릿에 설치하기 (행사 전, 인터넷 연결 상태)

각 앱에 대해 **따로** 진행합니다. 홈 화면 아이콘 2개가 생깁니다.

**Android (Chrome)**: `https://서버/fortune/` 접속 → 10초 대기 → 메뉴(⋮) → **홈 화면에 추가 / 앱 설치**. `https://서버/sky/` 도 같은 방법.

**iPad (Safari)**: `https://서버/fortune/` 접속 → 10초 대기 → 공유(⬆) → **홈 화면에 추가**. `https://서버/sky/` 도 같은 방법. iPadOS 는 오래 쓰지 않은 웹 앱 저장소를 지울 수 있으니 **행사 전날·당일 아침에 다시 열어 확인**하세요.

### B-3. 운영자 화면에서 준비 상태 확인

첫 화면의 작은 날짜 글자를 2.5초 안에 5번 두드리거나 주소 끝에 `#operator`. **오프라인 준비: 완료** 와 `저장됨 25/25` 처럼 전체 파일이 저장되었는지 확인합니다. '누락 파일'이 있으면 인터넷이 켜진 상태에서 **다시 확인** → 그래도 누락이면 새로고침 후 다시 확인. '준비 완료' 가 아닌 상태로 행사장에 가져가지 않습니다.

### B-4. 업데이트

새 빌드가 서버에 올라가도 앱은 **자동으로 바꾸지 않습니다.** 인터넷이 켜진 상태에서 운영자 화면 → '업데이트 확인' → 새 버전 대기 중이면 **체험이 끝난 뒤** '업데이트 적용(새로고침)'. 앱 1 을 업데이트해도 앱 2 캐시는 건드리지 않습니다.

## 비행기 모드 시험 (두 방법 공통, 필수)

1. 태블릿을 **비행기 모드**로 바꾸고 Wi-Fi 도 끕니다.
2. 두 앱을 완전히 종료한 뒤 다시 엽니다.
3. 앱 1: 카드를 양쪽으로 12장 넘기고, 가운데 카드 두 번 터치 → 운세 → 슬라이드 복귀까지.
4. 앱 2: 시간 4개 전환 → 별자리 설명 2개 이상 → 퀴즈 → 오답 → 힌트 2단계 → 정답 → 처음으로.
5. 새로고침 후에도 동작하는지, 태블릿 **재부팅** 후에도 동작하는지 확인합니다.

## 문제가 생겼을 때

| 증상 | 조치 |
|---|---|
| (방법 A) 파일을 눌렀는데 글자만 나오거나 깨짐 | 다른 브라우저(메모장 등)로 열린 것. 길게 눌러 **Chrome 으로 열기** |
| (방법 A) 그림이 안 보임 | 파일이 완전히 복사되지 않음(3 MB 안팎이어야 함). 다시 복사 |
| (방법 B) 오프라인에서 "사이트에 연결할 수 없음" | 설치 전 인터넷을 껐거나 저장소가 지워짐. 인터넷 켜고 앱을 열어 10초 대기 → 준비 완료 확인 |
| 준비 상태가 '미완료' | 주소가 HTTPS 인지, 서버에 `sw.js`·`precache-manifest.json` 이 있는지 확인 |
| 화면이 자동으로 꺼짐 | 운영자 화면 '화면 켜짐 유지 요청'. 미지원 기기는 설정 → 디스플레이 → 자동 잠금 '안 함' |
| 한글 키보드가 안 뜸(앱 2 퀴즈) | 기기 설정에서 한국어 키보드 추가 |

## 검증된 환경과 미검증 환경

- 검증: Chromium(Playwright) 자동 검수 — 방법 A 는 `file://` 로 열어 그림·글꼴·전체 흐름·외부 요청 없음 확인, 방법 B 는 설치 → 전체 사전 캐시 → 오프라인 재실행·새로고침·미방문 화면·앱 1 캐시 삭제 후 앱 2 실행 통과 (`docs/TEST_REPORT.md`).
- **미검증**: 실제 Android 태블릿 Chrome, iPad Safari 에서의 동작·보존·재부팅. 위 절차로 실제 행사 기기에서 확인한 뒤 `docs/TEST_REPORT.md` 의 미검증 항목에 결과를 적어 주세요.
